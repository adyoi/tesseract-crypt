Why Tesseract?

Tesseract is designed to be a single CLI tool combining public-key encryption and passphrase encryption, a built-in signature with sender pinning, per-chunk anti-tamper while streaming, and locked keys — a combination that does not exist in any other modern file-encryption tool in a single binary.

Design advantages

Hybrid X25519 + forward secrecy

Every message uses an ephemeral X25519 key; the static DH against the recipient's identity is still computed. Messages open only for the right recipient, and no message ever shares a static key.

Built-in sign-then-encrypt

Ed25519ph streaming is built into the encryption flow: encrypt -k alice.key -r bob.pub produces a signed message directly. Optional verification with --require-signer alice.pub (identity pinning).

Per-chunk anti-tamper

The header is the AAD for every chunk (header ‖ index ‖ final). Reorder, splice, and truncation are all detected cryptographically — not just an end-to-end check.

Constant-memory streaming

64 KiB chunks by default (4 KiB–16 MiB): multi-GB files are processed without loading the whole plaintext into RAM. Unlike Picocrypt, which caps files at 512 MiB.

Two modes, one format

encrypt -r recipient.pub (asymmetric) or --passphrase (symmetric) — the CLI rejects both at once, with none of the ambiguity of complex PGP flows.

Capped Argon2id + locked keys

Passphrases use Argon2id (memory-hard) with hard ops/mem caps when opening untrusted headers (anti-DoS). Private keys can be stored locked (TSK2) and unlocked per use with memory wiping.

PEM-like armor

TTY output is automatically wrapped in -----BEGIN TESSERACT MESSAGE----- — safe to copy-paste through email, chat, or any text channel.

Atomic output

Decryption writes to .part and renames only after the AEAD and signature succeed. Authentication failure = exit code 3, with no corrupted file at the destination.

Key rotation (rekey)

tesseract-crypt rekey rewraps an existing message for new recipients (optionally re-signing and checking the original signer) without touching the encrypted payload — rotate or extend access without re-encrypting the file.

Library + CLI hybrid

A C11 core (embeddable) + C++17 CLI, one binary named tesseract-crypt with the tscrypt alias on Linux, Windows, macOS, and BSD. MIT licensed.

Design positioning

Readiness, honestly. Tesseract is still v0.1.0 and not yet audited by a third party. age and GnuPG have been audited for years and are widely adopted — for critical production environments they remain the references. Tesseract offers a combination of features (public-key + passphrase, built-in signing with pinning, anti-tamper streaming, locked keys, memory hygiene) in a single modern CLI that no other tool has.

The technical edge does not claim "more secure than AES/GnuPG" — the encryption uses audited libsodium primitives (X25519, XChaCha20-Poly1305, Ed25519, Argon2id). What is new is the architecture: a 264-byte header format, hybrid key schedule, per-chunk AAD, and verified atomic writes — all documented in the Format Specification.
