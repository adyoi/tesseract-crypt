Spesifikasi format

Format biner pesan Tesseract: header tetap 264 byte ber-magic TSCR, lalu deretan chunk terenkripsi XChaCha20-Poly1305. Format v2 menambahkan pesan multi-penerima; seluruh byte ke-little-endian kecuali dinyatakan lain.

Header pesan (264 byte)

Header seluruhnya menjadi AAD (additional authenticated data) setiap chunk. Mengubah satu byte pun membuat dekripsi gagal.

Versi 2 (multi-penerima). Field di offset 40 lalu berisi jumlah penerima (u32, little-endian) dan bukan kunci publik; byte 44–71 dicadangkan dan wajib nol. Blok kunci per penerima mengikuti header — lihat key schedule multi-penerima.

Key schedule

Mode 1 — public-key (hybrid)

dh_eph  = X25519(eph_sk, recipient_pk)          # forward secrecy
dh_stat = X25519(sender_sk, recipient_pk)       # identity binding (nol bila anonim)
master  = BLAKE2b-256(key = dh_eph,
                      in  = dh_stat || salt || "tesseract-kdf-v1")

Mode 1, format v2 — multi-penerima

Sebuah data key acak 32 byte melindungi muatan; ia dibungkus sekali per penerima memakai rahasia DH milik penerima itu — derivasi wrap_i sama seperti v1, tetapi dihitung per penerima. Satu blok 80 byte dikeluarkan per penerima, sesuai urutan yang diberikan ke API: 

block_i = recipient pk (32) || XChaCha20-Poly1305(key = wrap_i,
                                   msg = data_key, nonce = base_nonce,
                                   aad = header(264) || recipient pk) (48)

wrap_i  = BLAKE2b-256(key = X25519(eph_sk, recipient_i_pk),
                      in  = X25519(sender_sk, recipient_i_pk) || salt || "tesseract-kdf-v1")

Pendekripsi memindai blok untuk mencari kunci publiknya sendiri, menurunkan wrap_i yang sama dan membuka data key — lalu berlanjut persis seperti v1 (chunk muatan memakai data key). Pesan yang tidak ditujukan ke kunci Anda ditolak dengan galat khusus. Header 264 byte tetap menjadi AAD setiap chunk, dan setiap blok dibungkus dengan AAD header || recipient pk, sehingga blok tidak bisa dipindah dari pesan lain maupun diurut ulang dalam senyap.

Mode 2 — passphrase

master = Argon2id(passphrase, salt, ops, mem)   # ops/mem dari header

Per chunk ke-i

subkey_i = crypto_kdf(32, i+1, "TSCHNK01", master)
nonce_i  = base_nonce XOR (i di 8 byte terakhir, big-endian)
aad_i    = header(264) || u64be(i) || u8(final)
ct_i     = XChaCha20-Poly1305(subkey_i, nonce_i, pt_i, aad_i)
Mengapa header jadi AAD tiap chunk? Karena setiap chunk di-ikat ke header + nomor urut + penanda akhir, percobaan reorder, splice, maupun truncation terdeteksi secara kriptografis — bukan sekadar checksum.

Cangkang berkas

v1: header(264) || (u32le len(ct_i) || ct_i)*
v2: header(264) || block_1(80) … block_N(80) || (u32le len(ct_i) || ct_i)*

Setiap chunk dibungkus panjangnya (4 byte little-endian) lalu ciphertext. Chunk terakhir ditandai flag final di AAD. Pesan kosong direpresentasikan sebagai satu chunk final berisi 0 byte plaintext.

Armor (PEM-like)

Biner dapat dienkode ke teks base64 dengan pembatas label:

-----BEGIN TESSERACT MESSAGE-----
b64
-----END TESSERACT MESSAGE-----
DataLabel armor
Pesan terenkripsiTESSERACT MESSAGE
Kunci privatTESSERACT PRIVATE KEY
Kunci privat terkunciTESSERACT PRIVATE KEY (LOCKED)
Kunci publikTESSERACT PUBLIC KEY

Dekripsi & inspect mendeteksi input ber-armor secara otomatis.

Berkas kunci (TSK1 / TSK2 / TSKp)

FormatUkuranIsi
TSK1 — privat (plain)164 magic(4) + x_pk(32) + e_pk(32) + x_sk(32) + e_sk(64)
TSK2 — privat (locked)232 magic(4) + x_pk(32) + e_pk(32) + salt(16) + ops(4) + mem(8) + nonce(24) + secret_aead(112)
TSKp — publik68 magic(4) + x_pk(32) + e_pk(32)

Pada TSK2, bagian privat — x_sk(32) + e_sk(64) — dienkripsi XChaCha20-Poly1305 dengan kunci Argon2id(passphrase, salt, ops, mem) menggunakan AAD konteks "tesseract-key-v1"; 16 byte terakhir adalah tag AEAD. Bagian publik sengaja disimpan terang agar fingerprint & ekspor publik berfungsi tanpa kata sandi.

Anti-DoS. Saat membaca header/blob tak tepercaya, parameter Argon2id dibatasi keras: maksimum 16 ops dan 4 GiB memori, minimum memori 64 KiB. Ini mencegah memori terkuras oleh berkas musuhan.
