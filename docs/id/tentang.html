Mengapa Tesseract?

Tesseract dirancang sebagai satu tool CLI yang menggabungkan enkripsi kunci publik dan passphrase, tanda tangan bawaan dengan pinning pengirim, anti-tamper per-chunk saat streaming, dan kunci terkunci — kombinasi yang tidak ada pada alat enkripsi file modern lainnya dalam satu biner.

Keunggulan desain

Hybrid X25519 + forward secrecy

Setiap pesan memakai kunci ephemeral X25519; DH statis dengan identitas penerima tetap dihitung. Pesan hanya terbuka untuk penerima yang tepat, tanpa ada pesan yang berbagi kunci statis.

Sign-then-encrypt bawaan

Ed25519ph streaming menyatu dalam alur enkripsi: encrypt -k alice.key -r bob.pub langsung menghasilkan pesan bertanda tangan. Verifikasi opsional dengan --require-signer alice.pub (pinning identitas).

Anti-tamper per-chunk

Header = AAD untuk setiap chunk (header ‖ index ‖ final). Reorder, splice, maupun truncation terdeteksi secara kriptografis — bukan sekadar cek awal/akhir file.

Streaming memori konstan

Chunk 64 KiB default (4 KiB–16 MiB): file multi-GB diproses tanpa memuat plaintext penuh ke RAM. Berbeda dari Picocrypt yang membatasi 512 MiB per file.

Dua mode, satu format

encrypt -r recipient.pub (asimetris) atau --passphrase (simetris) — CLI menolak keduanya sekaligus, tidak ada ambiguitas mode seperti pada alur PGP yang kompleks.

Argon2id berbatas + kunci terkunci

Passphrase memakai Argon2id (memory-hard) dengan batas keras ops/mem saat membuka header tak-tepercaya (anti-DoS). Kunci privat bisa disimpan locked (TSK2) dan di-unlock per pemakaian dengan pembersihan memori.

Armor PEM-like

Output ke TTY otomatis dibungkus -----BEGIN TESSERACT MESSAGE----- — aman disalin-tempel lewat email, chat, atau kanal teks lain.

Output atomik

Dekripsi ditulis ke .part dan hanya di-rename setelah AEAD dan tanda tangan sukses. Kegagalan otentikasi = kode keluar 3, tanpa file korup di tujuan.

Rotasi kunci (rekey)

tesseract-crypt rekey membungkus ulang pesan yang ada untuk penerima baru (opsional menandatangani ulang dan memeriksa signer asli) tanpa menyentuh payload terenkripsi — rotasi atau perluasan akses tanpa mengenkripsi ulang berkas.

Hibrida perpustakaan + CLI

Inti C11 (embeddable) + CLI C++17, satu biner tesseract-crypt dengan alias tscrypt di Linux, Windows, macOS, dan BSD. Lisensi MIT.

Posisi desain

Jujur soal kesiapan. Tesseract masih v0.1.0 dan belum diaudit pihak ketiga. age dan GnuPG sudah bertahun-tahun diaudit dan diadopsi luas — untuk produksi lingkungan kritis, keduanya tetap referensi. Tesseract menawarkan kombinasi fitur (pubkey + passphrase, tanda tangan bawaan dengan pinning, streaming anti-tamper, kunci terkunci, kebersihan memori) dalam satu CLI modern yang belum dimiliki tools lain.

Keunggulan teknis tidak mengklaim "lebih aman dari AES/GnuPG" — enkripsi memakai primitif libsodium yang diaudit (X25519, XChaCha20-Poly1305, Ed25519, Argon2id). Yang baru adalah arsitektur: format header 264 byte, key schedule hibrida, AAD per-chunk, dan penulisan atomik yang diverifikasi — semuanya terdokumentasi di Spesifikasi Format.
