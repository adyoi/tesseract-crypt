Kecepatan enkripsi

Berapa detik dan MiB/s yang dibutuhkan Tesseract, diukur end-to-end lewat CLI. Intinya: throughput payload simetris cepat, dan satu-satunya langkah mahal adalah Argon2id pada mode passphrase.

Angka rujukan Reproduksi Fitur

Metodologi

  • Diukur lewat CLI tesseract-crypt sungguhan, jadi angkanya mencakup start-up proses, I/O file, dan framing per chunk — bukan hanya cipher mentah.
  • Terbaik dari 3 kali jalan (scripts/bench.sh), yang menghapus derau cache dingin dan antivirus.
  • Payload: 16 MiB data acak, chunk default 64 KiB (kecuali baris ukuran chunk).
  • Build Release (-DCMAKE_BUILD_TYPE=Release), TESS_WARNINGS_AS_ERRORS=ON, libsodium upstream.
Host rujukan. Intel Core i3-2330M @ 2.20 GHz (2 core, Sandy Bridge 2011) pada WSL2 — mesin yang sengaja sederhana dan terbatas bandwidth. CPU modern jauh lebih cepat; anggap tabel ini sebagai batas bawah dan cara membandingkan antar operasi.

Pada host ini satu file 16 MiB dienkripsi jauh di bawah satu detik, dan jalan yang sama berulang dalam rentang sekitar 2×. Perbedaan antar baris ukuran chunk berada di dalam rentang derau itu — itu tidak menandakan keunggulan nyata satu ukuran chunk atas yang lain.

Membaca angkanya

Argon2id mendominasi mode passphrase

Perhatikan selisihnya: enkripsi public-key 16 MiB ≈ 0,8 d, sedangkan enkripsi passphrase ≈ 4,4 d. Sebagian besar selisih itu adalah derivasi kunci Argon2id (≈ 1,6 d, dan berjalan lagi saat dekripsi), bukan cipher-nya. Jika mengenkripsi banyak data dengan passphrase, turunkan satu kunci lalu enkripsi banyak pesan dengan kunci itu.

Throughput payload mengikuti CPU

XChaCha20-Poly1305 dan BLAKE2b bukan hambatannya — dual-core 2011 inilah hambatannya. Pada core desktop modern, AEAD libsodium biasanya mengalir pada 1–2 GiB/s dan tanda tangan Ed25519ph pada beberapa ratus MiB/s, yakni 20–100× angka ini. CLI menambahkan framing chunk dan satu pass ekstra untuk tanda tangan.

Penerima murah, tanda tangan menambah satu pass

Tiap penerima tambahan berbiaya satu X25519 + satu pembungkusan kunci 80 byte — dapat diabaikan dibanding payload nyata (lihat betapa dekatnya baris 3 penerima dengan yang 1 penerima). Sign-then-encrypt membaca plaintext satu kali lagi untuk menghasilkan tanda tangan Ed25519ph streaming.

Ukuran chunk hampir tak berpengaruh

Chunk 4 KiB → 1 MiB semuanya di band yang sama. Pakai default 64 KiB kecuali ada alasan: chunk lebih kecil mendeteksi korupsi lebih cepat dan menahan memori lebih rendah; chunk lebih besar mengurangi overhead framing pada disk yang sangat cepat.

Memori

Enkripsi dan dekripsi antar dua file bersifat streaming: memori konstan (beberapa buffer chunk) apa pun ukuran file. Jalur buffered — stdin/stdout, --text, dan enkripsi passphrase — menahan seluruh input di memori. Mode passphrase tambahan mengalokasikan working set Argon2id (256 MiB pada setelan MODERATE default).

Reproduksi

Benchmark-nya skrip shell POSIX kecil yang memanggil CLI, jadi berjalan di Linux, macOS, dan MSYS2/MinGW di Windows:

# build dulu
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# BIN [SIZE_MB]  — terbaik dari REPS (default 3) kali
scripts/bench.sh build/tscrypt 16

# jalankan lebih banyak untuk angka yang lebih tenang
REPS=5 scripts/bench.sh build/tscrypt 64
Catatan Windows. Dengan antivirus real-time aktif, jalan pertama tiap perintah bisa 10× lebih lambat saat scanner mengklaim executable dan DLL. Fitur best-of-N skrip menangani ini; angka steady-state mendekati Linux pada perangkat yang sama.
