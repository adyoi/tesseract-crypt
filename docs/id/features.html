Manajemen kunci

Setiap identitas adalah kunci X25519 (enkripsi) dan Ed25519 (tanda tangan) dalam satu file. Ada tiga format file — lihat spesifikasi format:

FileIsiKapan
NAME.key (TSK1)Kedua kunci rahasia, terangKeygen default
NAME.key (TSK2)Kedua kunci rahasia terenkripsi passphrase; bagian publik tetap terbacaDibuat dengan --passphrase
NAME.pub (TSKp)Hanya bagian publikAman dibagikan

keygen --passphrase melindungi kunci pribadi dengan Argon2id (biaya MODERATE libsodium sebagai default, dapat diubah lewat --kdf-ops N dan --kdf-mem MB). Bagian publik sengaja dibiarkan terbuka agar fingerprint dan ekspor pubkey tetap bekerja tanpa passphrase.

Di memori, material rahasia di-zeroize dengan sodium_memzero saat dibebaskan, dan sodium_mlock menyematkan skalar rahasia agar tidak tertukar ke disk.

# buat pasangan kunci dengan kunci pribadi terkunci
tesseract-crypt keygen -o alice --passphrase

# ekspor kunci publik (menanyakan passphrase)
tesseract-crypt pubkey -k alice.key -o alice.pub

# siapa saya?
tesseract-crypt info -k alice.key

Enkripsi hybrid public-key

Mode default. Setiap pesan memakai kunci ephemeral X25519 baru, sehingga satu kunci penerima dapat mendekripsi ribuan pesan tanpa kunci rahasianya pernah terekspos:

dh_eph  = X25519(eph_sk, recipient_pk)          # forward secrecy
dh_stat = X25519(sender_sk, recipient_pk)       # pengikatan identitas
master  = BLAKE2b-256(key = dh_eph,
                      in  = dh_stat || salt || "tesseract-kdf-v1")

Suku kedua DH mengikat identitas: pesan hanya bisa dibuka oleh penerima yang dituju, dan penyerang yang mengganti ciphertext tidak dapat membuatnya terdekripsi di kunci orang lain. Berikan -k sender.key untuk memakai suku pengirim tersebut sekaligus menandatangani (lihat di bawah); tanpa itu pesan anonim.

Pesan multi-penerima (format v2)

Ulangi -r untuk mengenkripsi satu pesan bagi satu tim. Sebuah data key acak 32 byte mengenkripsi payload; data key itu lalu dibungkus sekali per penerima memakai rahasia DH masing-masing:

tesseract-crypt encrypt -r alice.pub -r bob.pub -r carol.pub \
                        -k alice.key -i rahasia.txt -o tim.enc

Biaya tiap penerima tambahan hanya satu operasi X25519 + satu blok kunci 80 byte — dapat diabaikan dibanding payload nyata. Pendekripsi yang bukan penerima ditolak dengan galat khusus, sehingga "ini bukan untuk Anda" dapat dibedakan dari "ini rusak".

Mode passphrase

Bila tidak ada kunci publik tujuan, gunakan passphrase: --passphrase menurunkan master key dengan Argon2id (memory-hard) dari salt di header.

# enkripsi file / string hanya dengan passphrase
tesseract-crypt encrypt --passphrase -i catatan.txt -o catatan.enc
tesseract-crypt encrypt --passphrase --text "satu kalimat"

# dekripsi
tesseract-crypt decrypt --passphrase -i catatan.enc -o catatan.txt
Biaya. Argon2id sengaja mahal dan dijalankan di kedua sisi. Pada mesin rujukan biayanya ~1,6 d sebelum menyentuh payload, jadi mode passphrase untuk data sesekali, bukan pipeline massal. Lihat kinerja.

Parameter yang tertulis di header dibatasi keras saat membaca input tak tepercaya (≤ 16 ops, 4 GiB) agar file berbahaya tidak menghabiskan memori.

Sign-then-encrypt

Memberikan -k sender.key pada encrypt membuat tool menandatangani plaintext dengan Ed25519ph (varian streaming) dan menyimpan tanda tangan 64 byte di header. Karena seluruh header adalah AAD tiap chunk, tanda tangan diverifikasi sebagai bagian dari dekripsi — sebelum satu byte plaintext pun ditulis ke disk.

--no-sign melewatinya, dan enkripsi anonim cukup encrypt tanpa -k.

Tanda tangan detached

Terpisah dari enkripsi, untuk artefak rilis dan patch:

tesseract-crypt sign   -k alice.key -i rilis.tar.gz -o rilis.tar.gz.sig
tesseract-crypt verify -k alice.pub -i rilis.tar.gz -s rilis.tar.gz.sig

Memakai konstruksi Ed25519ph yang sama dengan sign-then-encrypt, sehingga file besar dialirkan dan tidak pernah di-buffer utuh.

Streaming, chunking & armor

AEAD per chunk

Payload dienkripsi dalam chunk yang diautentikasi independen (default 64 KiB, diubah lewat --chunk-size dari 4 KiB hingga 16 MiB). Tiap chunk mendapat subkey sendiri lewat crypto_kdf, nonce sendiri (base nonce di-XOR dengan indeks chunk), dan AAD header || indeks || final. Inilah yang membuat serangan reorder, splice, dan truncation gagal secara kriptografis, bukan sekadar korup diam-diam.

Kapan streaming?

OperasiPerilaku memori
encrypt/decrypt file → fileStreaming — memori konstan apa pun ukuran file (tess_seal_file / tess_open_file)
stdin / stdout / --textBuffered — seluruh input ditahan di memori
sign / verifyStreaming (Ed25519ph)

Armor

Output yang berakhir di TTY otomatis dibungkus base64 bergaya PEM; --armor memaksanya, dan decrypt/inspect mendeteksi input ber-armor secara otomatis:

-----BEGIN TESSERACT MESSAGE-----
...
-----END TESSERACT MESSAGE-----

Jaminan dekripsi

  • Verifikasi sebelum tulis. Ciphertext ditulis ke file .part yang baru di-rename ke nama akhir setelah AEAD (dan, bila ada, tanda tangan) sukses. Data tak-terautentikasi tidak pernah mencapai path tujuan.
  • Input ber-armor terdeteksi otomatis, jadi menempel balik blok base64 langsung berfungsi.
  • Penyematan pengirim dengan --require-signer signer.pub: bila pesan ditandatangani orang lain (atau tidak ditandatangani), dekripsi gagal dengan kode keluar 3 dan tidak ada file output yang ditulis.
  • Cek penerima. Pesan v2 yang tidak ditujukan ke kunci Anda ditolak secara eksplisit.
  • Deteksi truncation/reorder muncul dari desain AAD chunk — memotong aliran terdeteksi.

Inspeksi

Baca metadata tanpa kunci apa pun dan tanpa mendekripsi:

$ tesseract-crypt inspect -i tim.enc
format version : 2
mode           : public-key
recipients     : 3
signed         : yes

Portabilitas, build & pengujian

  • Platform. Linux, Windows (MSVC, MinGW, MSYS2), macOS, BSD — nama biner sama di mana-mana (tesseract-crypt, plus alias tscrypt).
  • Build. CMake ≥ 3.16 melawan libsodium (libsodium-dev, atau vcpkg). Opsi: TESS_BUILD_CLI, TESS_BUILD_TESTS, TESS_SANITIZE (ASan+UBSan), TESS_WARNINGS_AS_ERRORS, TESS_FUZZ (harness libFuzzer).
  • Suite uji. Delapan target ctest mencakup roundtrip, tamper, armor, format kunci, I/O file, tanda tangan detached, vektor known-answer terbit, dan multi-penerima — suite yang sama dibangun dan dijalankan di tiap platform di CI, plus job ASan/UBSan dan tiga fuzzer.
  • Distribusi. Repositori APT ber-tanda tangan GPG untuk Debian/Ubuntu amd64, paket RPM (Fedora/RHEL/openSUSE) dan PKGBUILD Arch siap pakai, serta artefak GitHub Release.
